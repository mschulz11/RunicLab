# .architektur.md – verbindliche Regeln für dieses Repository

Diese Datei ist eine **Anweisung**, keine Beschreibung. Wer hier Code ändert –
Mensch oder Agent – hält sich daran. Die ausführliche Begründung und der
Ist-Zustand stehen in [`docs/architektur.md`](docs/architektur.md); bei
Widerspruch gilt diese Datei.

## 1. Verschlüsselungsseiten erben, nicht kopieren

Jede Seite, die ein Verfahren zum Ver- oder Entschlüsseln anbietet, leitet von
`RunicLab.Views.CipherPageBase` ab und nutzt den gemeinsamen Block
`RunicLab.Views.CipherEingabe`.

```xml
<views:CipherPageBase xmlns:views="clr-namespace:RunicLab.Views"
                      x:Class="RunicLab.Views.CodeMeinVerfahren"
                      Title="Mein Verfahren">
    <ScrollView>
        <VerticalStackLayout Padding="30,0" Spacing="20">
            <!-- seitenspezifische Erklärtexte -->
            <views:CipherEingabe x:Name="CipherEingabeControl" />
        </VerticalStackLayout>
    </ScrollView>
</views:CipherPageBase>
```

Die Seite implementiert genau drei Methoden:

| Methode | Aufgabe |
| --- | --- |
| `EinstellungenAnwenden()` | Beschriftungen/Statuszeile aus den Einstellungen setzen, Vorschau (z. B. Gitter) auffrischen |
| `AktionAusfuehren()` | Eingabe verarbeiten, Ergebnis in `Eingabe.AusgabeText` schreiben |
| `EinstellungsSeiteErzeugen()` | Einstellungsseite zurückgeben |

Im Konstruktor nach `InitializeComponent()`: `EingabeVerwenden(CipherEingabeControl);`

Verboten in einer abgeleiteten Seite: eigenes `ToolbarItem` für die
Einstellungen, eigenes Eingabe-`Border`, eigener Aktions-`Button`, eigener
Ausgabe-`Border`, eigene `OnAppearing`-Aktualisierung der Beschriftungen – das
macht die Basisklasse. `OnAppearing` wird nur überschrieben, wenn zusätzlich
etwas Seitenspezifisches passieren muss (und ruft dann `base.OnAppearing()`).

## 2. Chiffre-Logik bleibt UI-frei

Neue Algorithmen gehören als reine Klasse nach `src/RunicLab/Models/` ohne
`Microsoft.Maui.*`-Typen und bekommen eine Testdatei unter
`tests/RunicLab.Tests/`, eingebunden per `<Compile Include>` in der
Test-Projektdatei. Was MAUI braucht, gehört in die `Views`-Schicht.

## 3. Ein gemeinsamer Ort pro Zuständigkeit

| Zuständigkeit | Ort |
| --- | --- |
| Algorithmus | `src/RunicLab/Models/` |
| Persistenz von Einstellungen | `src/RunicLab/Views/*Preferences.cs` (über `Preferences`) |
| gemeinsames Seitenverhalten | `src/RunicLab/Views/CipherPageBase.cs` |
| gemeinsames Seitenlayout der Ein-/Ausgabe | `src/RunicLab/Views/CipherEingabe.xaml` |
| Navigation/Registrierung der Seiten | `AppShell.xaml`, `Views/MainPage.xaml(.cs)` |

Wird ein Bedürfnis zum zweiten Mal gebraucht, wandert es in die Basis (Klasse
oder Control) – nicht in eine dritte Kopie.

## 4. Was hier nie passiert

- Keine Installer/MSIX-Artefakte; ausgeliefert werden nur signierte APK (arm64)
  und Windows-ZIP.
- Keine Secrets, Keystores oder lokalen Pfade im Repository.
- Keine Netzwerk-, Telemetrie- oder Cloud-Aufrufe.
- Keine Zielplattform außer Android und Windows als Release-Ziel; iOS,
  Mac Catalyst und Tizen bleiben höchstens kompilierbar.

## 5. Pflicht vor jedem Merge

```bash
dotnet build src/RunicLab/RunicLab.csproj -f net10.0-windows10.0.19041.0
./scripts/test.sh
```

Die CI startet erst nach dem Merge auf `master` (Issue #13) – ein Pull Request
ohne lokalen grünen Build ist ungeprüft. Strukturänderungen (neue Ordner, neue
Projekte) aktualisieren `docs/architektur.md` und bekommen ein ADR unter
`docs/adr/`.
